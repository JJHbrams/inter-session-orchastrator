통합 멘션과 좌장 기본 라우팅

수신 모드 버튼을 없애고 좌장을 같은 멘션 대상으로 두며, 멘션 없는 실행 요청은 좌장이 먼저 판단한다.

한눈에 보기

  • 목적: 사용자가 수신 모드를 고르지 않고 이름과 내용으로 토론을 진행한다.
  • 현재 상태: AC-1~AC-4 구현·검증 완료. 전체58/58, 실제 브라우저·새 좌장과 독립 수용 검토를 확인했다. 프로젝트 전체는 building이다.
  • 핵심 결론: 명시 멘션은 직접 전달하고, 무멘션은 좌장 한 명에게 먼저 전달한다.
  • 판단 근거: 멘션 후보에는 이미 좌장이 있으나 현재 무멘션은 참여자 전체이고 별도 수신 버튼이 있다. 기존 좌장은 질문별 membership ID로 위임할 수 있다. (직접 코드 확인, 2026-10-22)
  • 결정: 새 auto 모드를 사용하고 기존 routingMode와 명시 ID 요청은 호환한다.
  • 다음 행동: 기존 외부 세션의 자동 wake·host 제출/응답 검증은 후속으로 유지한다.
  • 최종 갱신: 2026-10-22, Asia/Seoul.

1. 의도 (Intent)

‘참여자에게 / 좌장에게’ 선택을 제거한다. 좌장도 일반 참여자처럼 @별칭으로 직접 지정한다. 별칭을 쓰지 않은 실행 요청은 좌장이 내용·참여자 설명·대화 맥락을 읽고 필요한 참여자에게 질문/작업을 보내거나 직접 답한다. 명시 멘션은 다른 세션으로 자동 확대하지 않는다.

불변식: 원래 세션·메시지·첨부·전달 snapshot을 보존한다. 멘션 오타나 좌장 부재가 전체 전달로 바뀌면 안 된다. 이미 전달 여부가 unknown인 작업을 자동 재전송하지 않는다. 기존 외부 세션 자동 wake는 이번 변경과 구분한다.

2. 수용 기준 (Acceptance)

ID 사용자에게 보이는 결과 검증 방법
AC-1 수신 모드 버튼이 없고 좌장도 역할 표시와 함께 멘션 후보에 나온다. 좌장·참여자·혼합 멘션은 그 대상만 받는다. 브라우저 후보/키보드·미리보기·실제 저장 수신자, Store/HTTP
AC-2 멘션 없는 실행 입력은 활성 전용 좌장 한 명에게 먼저 전달된다. 부재·준비 안 됨·unknown·불명확/읽기 전용 멘션은 전송 차단하며 초안 유지, 전체로 대체하지 않는다. 게시·알림은 실행하지 않는다. 격리 UI와 Store 경계 테스트
AC-3 좌장이 입력·역할 설명·대화 맥락에 맞는 참여자에게 구체적으로 위임하고 이유를 발화한다. 이미 직접 지정된 대상에게 동일 입력을 중복 위임하지 않는다. coordinator 테스트와 새 검증용 좌장의 실제 질문·공유 발화/수신자 확인
AC-4 원래 기록·첨부·멱등 snapshot·예산·unknown 정책과 협력 pull을 유지한다. 과거 chair/mentions 모드 및 MCP 명시 ID는 호환한다. 전체 회귀·기존 DB 읽기 전용 대조·재시작·이전 키 replay

3. 확정 사실 (Facts)

사실 근거
UI는 recipientMode를 body와 함께 보내고 Store가 멘션을 재검증한다. app.js, store.js
mentions 모드의 무멘션은 전용 좌장을 제외한 전체다. Store.post
별도 좌장은 speech/questions/proposal과 첨부 ID를 반환한다. ChairCoordinator, Claude runner
기존 모델 입력은 위임 대상만 나열해 좌장이 자기 별칭을 모르는 실제 혼합 응답이 관측됐다. 자기 별칭·역할도 별도 제공한다. ChairCoordinator.context와 격리 실제 응답, 2026-10-22
참여자는 협력 MCP pull 방식이다. 기존 실행 명세·HTTP 경로

선택지

UI 수신 버튼 유지, 모든 무멘션을 전체로 전달, 좌장을 기본 수신자로 사용하는 방식을 비교했다.

평가기준

입력 단계 수, 명시 대상 보장, 불필요한 호출과 대화 확산이 기준이다.

비교

방식 입력 단계 명시 대상 보장 무멘션 확산
수신 버튼 매번 선택 모드에 따라 의미가 다름 전체
전체 기본 단순 멘션은 보장 전원 호출
좌장 기본 단순 직접 멘션 우선 좌장이 필요한 대상만 선택

결정

브라우저는 auto 모드를 전송한다. 기존 mode를 재해석해 과거 키를 깨지 않고, 새 모드에서만 무멘션 좌장 경유 정책을 적용한다. 명시 멘션 대상은 membership ID로 동결한다. 좌장에는 참가자 설명과 현재 직접 수신자도 전달해 불필요한 재위임을 막는다. 같은 대상에게 새 쟁점을 묻는 후속 질문은 허용하고, 실행 멘션을 제거한 본문이 원 요청과 같은 재발행만 서버에서 차단한다.

재검토 조건

명시 수신자 이외로 전달되거나 좌장 부재가 전체 배포로 바뀌면 즉시 라우팅을 재검토한다. 새 쟁점의 후속 질문까지 차단하거나 실제로 받지 않은 답변을 취합한 것으로 표시해도 수정한다.

12. 검증 결과

AC 근거 결과
AC-1 실제 후보에서 @유→유리아 Claude·좌장→Enter, 직접/혼합 수신자 DB 대조 수신 버튼0개. @민수는 민수만, @유리아 @민수는 두 명만
AC-2 실제 무멘션 최초 수신·좌장 부재/오타 오류·초안 보존·게시 최초 대상은 유리아 한 명. 전체 배포 없음. 게시0 deliveries
AC-3 새 실제 좌장과 역할이 다른 검증용 참여자 README 검토를 문서 담당 지수 한 명에게 선택하고 이유·질문을 공개. 코드 담당 민수 제외
AC-4 전체58/58·원래11개 테이블 SHA 일치·멱등/첨부/unknown/pull 회귀 원래 기록 보존. 기존 mode/hash와 수신자 snapshot 유지

실제 혼합 멘션에서 좌장이 자기 이름을 모르는 문제가 드러나 chairIdentity를 추가했다. 같은 검증 대화 ID를 재개해 자기 별칭 유리아와 좌장 역할을 정확히 답했으며 새로운 질문은0개였다. 새 후속 질문은 허용하고 멘션 제거·공백 정규화 뒤 같은 본문을 기존 직접 수신자에게 다시 보내는 것만 차단한다.

검증용 좌장은 실제 Claude 대화다. 민수·지수는 설명과 협력 membership을 갖춘 가상 참여자이며, 이 검증에서 두 외부 모델을 깨우거나 답변을 받았다고 주장하지 않는다. 좌장이 선택한 요청은 queued 상태로 저장되며 참여자가 MCP pull로 받는 기존 의미를 유지한다.

13. 파란 멘션 강조 후속

입력창과 토론 대화에서 토론장의 유효한 @별칭에 같은 파란 배경 #2453a0을 적용한다. 입력창은 native textarea를 유지하고, 접근성 트리에서 숨긴 backdrop에 배경만 그린다. 커서·선택·본문을 교체하지 않으며 스크롤과 크기 변화를 동기화한다. 전달 대상과 서버 라우팅은 변경하지 않는다.

경로 직접 확인한 결과
실제4318 입력창 @수아·@마야·@유리아 세 범위만 강조. 미등록 이름·이메일·코드의 @는 제외. 원래 초안은 검증 직후 복원
격리4320 대화 사용자·참여자·좌장 게시의 일곱 멘션 배경이 모두 rgb(36,83,160). 미등록 이름은 투명 배경, 이메일·코드는 멘션 span 없음
자동완성 @수→Enter 후 본문 @수아 와 강조 span이 일치. 기존 멘션 목록과 선택 동작 유지
회귀 npm test 62/62. 새 DOM 검증은 HTML 주입 차단, 공유 parser 범위, native textarea 동일성·선택·form 연결·본문 보존·스크롤 동기화·참여자 변경을 확인

실제 IME 조합이나 OS 클립보드를 이번 후속에서 별도로 자동화하지 않았다. textarea를 유지하는 구현과 기존 첨부·초안 회귀 테스트로 해당 경로를 보존했다. 검증 fixture는 별도 DB의 게시 세 건만 사용하며 모델 요청은0건이다.

강조 검증 화면. 최초 라우팅 검증58개와 별도로 현재 전체 테스트는62개다.
